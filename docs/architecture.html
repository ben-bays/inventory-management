Factory Inventory Management System

Architecture overview — Vue 3 frontend, FastAPI backend, in-memory mock data (no database)

Tech Stack

Frontend

Vue 3 + Vite

  • Vue 3 — Composition API
  • Vue Router 4 — client-side routing
  • Axios — HTTP client
  • Vite — dev server / bundler
  • Runs on localhost:3000 (dev)
Backend

Python + FastAPI

  • FastAPI — REST API framework
  • Pydantic — request/response validation
  • Uvicorn — ASGI server
  • Managed with uv
  • Runs on localhost:8001 (dev)
Data

In-Memory Mock Data

  • Static JSON files in server/data/
  • Loaded once at startup by mock_data.py
  • No database — no persistence between restarts
  • Filtering done in Python, in memory

Request / Data Flow

1

User adjusts a filter

The global FilterBar.vue writes to shared singleton refs in useFilters.js (time period, warehouse, category, order status).

2

View reacts and calls the API client

A view (e.g. Dashboard.vue) reads getCurrentFilters() and calls a function in api.js, such as api.getDashboardSummary(filters).

3

Axios issues an HTTP GET

api.js builds query params from active filters and calls the FastAPI server at http://localhost:8001/api/....

4

FastAPI filters in-memory data

main.py applies apply_filters() / filter_by_month() over the Python lists loaded by mock_data.py — no database query, just list comprehensions.

5

Pydantic validates the response

Each endpoint's response_model (e.g. InventoryItem, Order) validates and serializes the filtered data back to JSON.

6

Vue stores raw data, derives the rest

The response is stored in a raw ref (e.g. allOrders). computed() properties derive chart data, totals, and table rows — cached until dependencies change.

7

Template re-renders

Vue's reactivity system updates only the DOM nodes bound to changed computed values.
